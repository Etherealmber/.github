## 🏛️ Who we are

**Etherealmber** is a software organization based in Morocco, building one connected platform for the businesses that keep the country running: wholesalers, shops, warehouses, workshops and family companies.

We ship **one product family, not a pile of disconnected tools**. Atlas Commerce is the operational core — stock, checkout, invoicing, purchasing, staff. Everything else connects to it: the Android app moves with it, the Rust desktop client mirrors it, and the shop front we are building now reads directly from it.

No opaque SaaS subscriptions, no dedicated servers, no locked-in vendor. Every deployment lives in the client's own Cloudflare account, and the business owns the database, the backups and the code.

## 📦 Products

### 🧾 Atlas Commerce — web core · <!--VER:atlas-commerce-->`0.9.2-beta`<!--/VER-->

The operational core, self-hosted on Cloudflare Workers. Fully themeable (light / dark, densities, text sizes), French-first, phone-aware.

<details open>
<summary><strong>What ships today</strong></summary>

- **Stock** — multi-warehouse, bin locations, lots + FEFO expiry, thresholds, audited movements, rolling inventory, transfers, kits/BOM
- **Point of sale** — VR receipts without VAT, multi-method payments, refunds, cash drawer balance
- **Invoicing** — VAT invoices, receivables and due dates, credit notes, CSV export, status pipeline with journal
- **Purchasing** — bills, receptions, supplier references, price breaks
- **Parties** — clients with ICE and credit limits, vendors, employees
- **Scan & OCR** — native barcode scanning, photo-driven product requests, invoice/quote OCR
- **Atlas Agent (AI)** — grounded on live data, per-action permissions, explicit confirmation before writes
- **Authentication** — password + OTP, WebAuthn / passkeys, 60-second single-use QR pairing, Turnstile, rate limiting
- **Administration** — users and roles, API keys + webhooks, encrypted D1 → R2 backups, audit log, version journal
- **Partner API v1** — scoped keys, `Idempotency-Key` writes, OpenAPI document
- **Output** — printable labels (QR + CODE128 + price), reports, alert center

</details>

<details>
<summary><strong>Engineering delivery</strong></summary>

- Full roadmap **v209 delivered — 10 / 10 workstreams** (scan-first operations, lots/FEFO, alert center, supplier parts, status pipeline, labels, kits/BOM, attachments QC, bin locations, webhooks)
- **CI guards** — no API or front-end change merges without passing the gates
- **GitHub automations** — automatic issue triage (FR/EN), self-repair bots, release/support sync blocks
- Self-hosting documentation: `SETUP.md`, Android ↔ Worker contract, WebAuthn guide, finance API docs

</details>

### 📱 Atlas Commerce for Android · <!--VER:atlas-commerce-android-->`1.8.2`<!--/VER-->

Native Kotlin + Jetpack Compose (Material 3), `minSdk 28` — Android 9 and up, including handheld scanners. Releases are signed, emulator-verified and distributed through GitHub Releases plus a mirrored update channel.

<details open>
<summary><strong>What ships today</strong></summary>

- **Strict multi-server & multi-account isolation** — `AES-256-GCM` per server, `SHA-256` scoped offline caches, full purge of carts, caches, avatars, notifications and AI chats on switch
- **Atlas Agent synchronized with the web** — shared conversation threads via `/api/admin/agent/threads`, live token quota bars
- **Guided onboarding** — server URL → live `/api/health` probe (D1 + R2) → sign-in, with saved servers
- **Sign-in** — password + OTP, one-tap email verification link, or QR pairing from the PC
- **Operations** — stock lookup, POS quick sales, receipts, invoices, barcode scanning, alert inbox
- **Profile / settings split** — account and POS customisations vs. devices, quota bars, OTA updates, cache controls
- **Camera privacy** — hardware stays off until you start, unbinds on leave, every scan cancellable
- **Local device unlock** — opt-in biometrics or device PIN after a manual sign-in; the account password is never stored
- **Consent-based crash reporting** — Firebase Crashlytics and Analytics off by default
- **Finance reports** — monthly PDF statements with an in-app history, private per-account cache, deletable from Settings

</details>

### 🖥️ Atlas Commerce for Desktop · <!--VER:atlas-commerce-desktop-->`0.3.2`<!--/VER-->

Native Rust + egui (fastframe) client for Windows, macOS and Linux — no browser engine, no telemetry, `reqwest` + rustls.

> ⏸️ **Paused on purpose.** The desktop client is not being extended until the **login issue** on the web app is fixed. Once sign-in is solid, desktop work resumes from the 0.3.2 base already shipped.

<details open>
<summary><strong>What ships today</strong></summary>

- **Dashboard** — balance, stock value, counters, unpaid sales, monthly activity, latest invoices
- **Products & stock** — search, create, thresholds, and native movement history with entry / exit / adjustment
- **Sales** — invoice history and quick sales with `Idempotency-Key`
- **Clients** — three-step creation form with validation and history
- **Finance** — combined native reports, authenticated loading, real expense breakdown
- **Atlas Agent** — persistent conversation with quota and block state from `/api/agent/policy`
- **Sign-in** — password + OTP, `atlascommerce://verify` deep link, native QR approval v2
- **Desktop life** — custom title bar, tray, single instance, start-at-login, native notifications
- **Security** — device fingerprint bound to sessions, no password stored, `0600` files, session ends on focus loss
- **Updates** — GitHub Releases only, `update.json`, `checksums.txt`, Ed25519 signature, blocking mandatory updates

</details>

### 🛍️ Atlas Shop — *in progress*

The customer-facing storefront, reading products, stock, prices and media straight from Atlas Commerce through Partner API v1 and webhooks. No second database to keep in sync.

### 🎫 Support portal — *planned*

**Not the in-app `/support` page** — that one is a contact form inside Atlas Commerce. This is a **separate help platform**: knowledge base, ticket submission and history, status page, and tickets linked to real customer and order records so an agent opening a ticket sees the merchant's actual stock, invoices and devices. Nothing built yet beyond the `SUPPORT-SYNC` hooks.

## 🧭 How we build

```text
one system        products share data, not just branding
edge-first        Cloudflare Workers · D1 · R2 · Durable Objects
no lock-in        the client owns the account, the data and the deploy
private by default secrets in Wrangler, never in the repo
native clients    Kotlin and Rust — no browser engine on phone or desktop
French terrain    UI written for the field, in the language of the field
verifiable work   CI guards, issue bots, signed releases
```

- 🔒 **Ownership over convenience** — the business owns the database, the backups and the code
- ⚡ **Fast where it hurts** — one scan, one keypress, one ticket
- 🧩 **Boring infrastructure** — one Worker, one SQLite database, one bucket
- 🇲🇦 **Local reality first** — ICE/IF, VAT, VR receipts, French labels, phone-first usage
- 📖 **Working in the open** — MIT where we can, READMEs that explain the system
